## Пример №1
| | |
| :--- | :--- |
|**Объект:**| Cетевой адаптер в ПК|
|**Уровень OSI:**| Канальный уровень L2 + Физический уровень L1|
**Описание:**
- Сетевой адаптер отвечает за умение устройства подключаться к LAN. Он берет данные, упаковывает их в кадры/фреймы, добавляя туда же заголовок (MAC-адрес ПК и MAC-адрес получателя) и концевик для проверки контрольной суммы.
- Мой сетевой адаптер в пк является беспроводным, так что, чтобы передать данные на роутер в начале кадра, он посылает "чистую" радиоволну, которая показывает роутеру, что сейчас начнут поступать данные, а роутер ловит эту радиоволну. Затем эта волна быстро видоизменяется, тем самым передавая данные, после полной передачи сетевой адаптер обрывает подачу этой волны, что показывает роутеру, что кадр кончился. 

## Пример №2
| | |
| :--- | :--- |
|**Объект:**| Домашний роутер/маршрутизатор|
|**Уровень OSI:**| Cетевой уровень L3|
**Описание:**
- Роутер связывает LAN с WAN. Он принимает и отсылает пакеты данных.
- При передаче (LAN->WAN) он достает пакет из переданного кадра, отбрасывая заголовок с MAC-адресами отправителя и получателя. Затем читает IP-адрес получателя, накладывает маску своей подсети, если совпадает с его подсетью - LAN, если нет - провайдеру. Формирует новый кадр, добавляя свой MAC-адрес как отправителя и MAC-адрес следующего устройства (например роутер провайдера) как получателя.
- При получении (WAN->LAN) роутер также достает пакет из переданного кадра, отбрасывая заголовок с MAC-адресами отправителя и получателя. Затем читает IP-адрес получателя, накладывает маску своей подсети, смотрит по таблице маршрутизации, видит, что устройство-получатель находится в его подсети, идет искать в ARP-таблице MAC-адрес устройства, упаковывает в кадр и отправляет. юхууу

## Пример №3
| | |
| :--- | :--- |
|**Ошибка:**| Ошибка проверки SSL/TLS сертификата|
|**Уровень OSI:**| Уровень представления L6|
**Описание:** Эта ошибка возникает, когда ПК и Сервер не смогли договориться как зашифровать информацию, то есть не нашлось общего протокола, который есть у обоих. Например ПК запрашивает современный протокол, а сервер старый. В итоге в браузере выскакивает ошибка "cоединение не защищено".

## Пример №4
| | |
| :--- | :--- |
|**Система:**| Протокол DHCP (Dynamic Host Configuration Protocol) |
|**Уровень OSI:**| Прикладной уровень L7 |
**Описание:** DHCP выдает IP-адреса устройствам при их подключении к сети. При подключении ПК к Wi-Fi, DHCP-клиент с ПК отправляет в сеть широковещательный запрос на выдачу IP-адреса данному устройству. DHCP-сервер на роутере видит и присылает свободный IP-адрес, который ОС ПК затем применяет для настроек сети.
